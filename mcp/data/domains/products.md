# 商品

## 用户目标

处理普通商品、店铺商品、组合装、类目、BOM、历史成本价和商品供应商关系。先判断用户说的是内部 SKU、款号还是店铺 SKU。

## 能力路由

| 业务能力 | 类型 | action |
| --- | --- | --- |
| 普通商品上传 / 按 SKU 查询 / 按款查询 | 写入 / 查询 | `jushuitan_itemsku_upload` / `sku_query` / `mall_item_query` |
| 店铺商品上传 / 查询 | 写入 / 查询 | `jushuitan_skumap_upload` / `skumap_query` |
| 组合装上传 / 查询 | 写入 / 查询 | `item_combinesku_upload` / `combine_sku_query` |
| 类目上传更新 / 查询 | 写入 / 查询 | `webapi_itemapi_category_addorupdate` / `category_query` |
| BOM 上传 / 查询 | 写入 / 查询 | `webapi_itemapi_bom_save` / `webapi_itemapi_bom_getskubompagelist` |
| 历史成本价上传 / 查询 | 写入 / 查询 | `jushuitan_itemsku_costprice_upload` / `webapi_itemapi_itemsku_gethistorycostpricev2` |
| 多供应商上传更新 / 查询 | 写入 / 查询 | `webapi_itemapi_suppliersku_save` / `webapi_itemapi_suppliersku_getsupplierskulist` |

## 执行要点

- 先判断用户提供的是内部 SKU、款号、店铺 SKU 还是平台商品标识，再选择普通商品、按款或店铺商品能力。
- 普通商品上传单次最多200个。更新时“字段不传”表示保持原值，“字段传空”可能清空原值，只提交用户明确要修改的字段。
- 普通商品全量查询按修改时间分段获取，单次时间范围不得超过7天；数据量大时使用更小时间窗口并按时间升序连续拉取。
- 按款查询要求ERP已开启“按款显示”；单款超过1000个商品编码时改用按 SKU 查询。
- 店铺商品上传主要适用于商家自有商城且单次最多50个；店铺商品查询不覆盖淘系和拼多多时，应说明需要对应平台能力，不把“查不到”解释为商品不存在。
- 组合装没有独立实际库存，可组装数来自子商品库存；组合装关系与生产BOM是不同业务，不能互相替代。
- BOM 查询只有在ERP维护了商品主料后才可能返回数据；无结果时先提示检查BOM主料配置。
- 历史成本价属于敏感经营数据，只按用户要求展示，并明确成本对应的 SKU 和生效范围。
- 同一 SKU 关联多个供应商时，官方接口可能需要按供应商分别写入；应明确每次调用对应的独立业务意图和业务对象。
- 批量写入按接口实际返回汇总成功和失败项，不虚构逐项状态；结果未知时不得自动重试。

## 结果呈现

- 商品列表优先展示 SKU、款号、商品名称、规格和启用状态；店铺商品额外展示店铺商品编号与店铺 SKU。
- 金额明确标注“销售价”或“成本价”及单位，不把历史成本价描述为当前售价。
- 组合装和 BOM 要展开说明成品与子件关系；可组装数属于计算口径，不能写成实物库存。
- 批量上传按成功数、失败数和可识别的失败 SKU 汇总；上游没有逐项结果时只说明整批受理情况。
- 查询为空时说明使用的是内部 SKU、款号还是店铺 SKU，并提示可能的平台能力、时间窗口或配置限制。

## 典型问题

- “SKU A001 在聚水潭叫什么、卖多少钱？”：按 SKU 查询，给出商品名称、规格、销售价和启用状态。
- “这个组合装最多还能组多少套？”：先查组合关系，再结合子件库存计算并逐项说明短板 SKU。
- “把这批商品成本更新一下”：逐项核对 SKU、成本和生效条件，提交后报告整批与失败项，不展示原始 JSON。
