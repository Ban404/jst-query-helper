# 播种

## 用户目标

处理仓库播种批次、播种车或播种柜绑定、解绑、状态校验和播种结果回传。

## 能力路由

| 业务能力 | 类型 | action |
| --- | --- | --- |
| 获取播种批次信息 | 查询 | `jushuitan_wave_get` |
| 绑定播种车 | 写入 | `webapi_wmsapi_wave_bindbinidcarryid` |
| 播种回传（出库 / 不出库） | 写入 | `jushuitan_seed_callback` / `jushuitan_seed_return` |
| 按播种车解绑出库单 | 写入 | `webapi_wmsapi_wave_unbindinoutbycarryid` |
| 绑定播种柜号和播种车 | 写入 | `jushuitan_binid_carryid_bind` |
| 解绑批次拣货车或播种车 | 写入 | `webapi_wmsapi_wave_unbindwavecarryid` |
| 校验播种车状态 | 查询 | `jushuitan_carryid_check` |

## 执行要点

- 开始作业前先获取播种批次信息，确认批次、出库单和待播种范围。
- 绑定播种车前先校验车辆状态是否可用，再确认播种车、播种柜或格口标识，避免覆盖正在使用的关系。
- “绑定播种车”和“绑定播种柜号与播种车”处理的关系不同，应按现场设备和批次流程选择。
- 回传前明确本次结果是否需要更新为出库；“播种回传（不出库）”只做播种，不更新播种出库状态。
- 解绑时区分“按播种车解绑出库单”和“解绑批次的拣货车/播种车”，先查询当前绑定关系再操作。
- 批量作业按实际接口请求汇总成功、失败和状态未知项；状态未知时先查批次或车辆状态，不自动重新绑定或回传。
- 用户描述现场异常时优先给出当前批次、车辆状态、绑定关系和可执行下一步，不只返回接口错误码。

## 结果呈现

- 播种批次先展示批次号、波次、订单范围、应播数量、已播数量和当前阶段。
- 车辆与柜号操作必须同时说明对象编号和绑定关系，避免用户只看到“成功”却不知道绑定到哪里。
- 回传结果区分“完成播种并出库”和“仅完成播种不出库”；这两种结果不能使用同一句完成提示。
- 批量结果按成功、失败和未知状态汇总；未知时给出需要查询的批次或车辆，不自动重复绑定、解绑或回传。
- 现场异常回答先给当前状态，再给可执行下一步，例如释放车辆、重新绑定格口或核对批次，不展示无意义的原始错误对象。

## 典型问题

- “这辆播种车为什么不能用？”：校验车辆状态，并结合现有批次/柜号绑定说明占用原因。
- “批次 W001 播完了吗？”：展示应播、已播、未播数量和是否已回传出库。
- “本批只播种不要出库”：明确选择不出库回传，结果中再次注明未更新出库状态。
