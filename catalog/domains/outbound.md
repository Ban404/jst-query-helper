# 出库

## 用户目标

查询销售出库和采购退货，执行仓库出库发货，创建、查询或取消采购退货。

## 能力路由

| 业务能力 | 类型 | action |
| --- | --- | --- |
| 销售出库查询 | 查询 | `orders_out_simple_query` |
| 出库发货 | 写入 | `orders_wms_sent_upload` |
| 采购退货上传 | 写入 | `webapi_wmsapi_purchaseout_createbatch` |
| 采购退货查询 | 查询 | `purchaseout_query` |
| 采购退货取消 | 写入 | `jushuitan_purchaseout_cancel` |

## 执行要点

- “订单发货了吗”先读取[订单](orders.md)判断订单状态，再用销售出库确认是否产生出库单及仓库执行结果。
- 分销订单或线上发货订单可能不产生当前商家侧销售出库单；查不到出库单时不能直接判断未发货。
- 全量或增量查询销售出库时优先按官方 `start_ts` 行版本游标连续拉取，避免分页过程中数据变化导致漏单。
- 区分订单层发货与仓库出库发货。仓库出库发货前需在ERP配置有效的物流公司及编码，并结合[基础信息](basic-info.md)核对。
- 采购退货需明确供应商、原采购或入库关系、SKU、数量和退货仓库；查询时区分待退、已出库和取消等状态。
- 采购退货取消仅支持本仓单据，不支持已推送到三方仓的单据；先查询单据归属再执行。
- 出库结果涉及收件信息时只展示任务所需字段，并说明受限平台可能无法通过普通ERP接口返回敏感字段。

## 结果呈现

- 销售出库优先展示订单号、出库单号、仓库、出库状态、出库数量、物流公司、物流单号和时间。
- “是否发货”同时区分订单已标记发货、仓库已出库、物流已有单号三个阶段；缺少某阶段证据时明确说明。
- 采购退货展示退货单号、供应商/原采购关系、退货仓、数量和状态，不与客户售后退货混淆。
- 查询使用游标时说明覆盖到的时间或最新游标；空结果需提示分销或线上发货不一定产生本商家出库单。
- 写入部分成功时按订单或退货单列出失败原因；不输出无关的完整收件地址。

## 典型问题

- “SO001 是不是已经从仓库发走了？”：展示订单发货、销售出库和物流三个阶段的证据。
- “今天上海仓出了多少单、多少件？”：订单数与商品件数分别汇总，并说明游标覆盖范围。
- “取消 PO001 的采购退货”：先查退货单归属和状态，再执行并给出退货单号与最终处理结果。
