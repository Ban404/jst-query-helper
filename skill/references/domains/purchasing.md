# 采购

## 用户目标

查询或处理采购单、供应商、加工单、采购标签和预约入库，跟进采购状态、到货与后续入库。

## 能力路由

| 业务能力 | 类型 | action |
| --- | --- | --- |
| 采购单上传 / 查询 | 写入 / 查询 | `jushuitan_purchase_upload` / `purchase_query` |
| 供应商上传 / 查询 | 写入 / 查询 | `supplier_upload` / `supplier_query` |
| 加工单上传 / 查询 | 写入 / 查询 | `jushuitan_manufacture_upload` / `jushuitan_manufacture_query` |
| 采购或加工单标签 | 写入 | `jushuitan_purchaselabel_upload` |
| 修改采购单 | 写入 | `webapi_wmsapi_openpurchase_editpurchase` |
| 变更采购单状态 | 写入 | `jushuitan_purchase_change_status` |
| 作废采购、加工或预约入库单 | 写入 | `webapi_wmsapi_purchase_cancel` |
| 预约入库上传 / 查询 | 写入 / 查询 | `jushuitan_appointmentin_upload` / `jushuitan_purchasebooking_query` |

## 执行要点

- 先区分采购单、加工单和预约入库单；三者虽然部分状态操作共用接口，但业务对象和必填字段不同。
- 供应商上传以名称或供应商编码是否已存在判断新增或修改。名称存在歧义时先查询供应商，避免覆盖错误主体。
- 创建采购单时核对供应商、SKU、数量、价格、仓库和外部业务单号；加工生产需求使用加工单，不伪装成普通采购。
- “采购到哪了”先查采购单状态；采购查询不代表实际入库数量，需要继续读取[入库](inbound.md)核对已入库明细。
- 修改待审核采购单可以涉及更多字段；已审核采购单通常只允许修改物流、备注等有限字段，必须先查询当前状态。
- 修改采购明细时，官方接口可能把未传入的 SKU 明细删除，因此不能只发送局部明细，必须按官方要求携带完整明细集合。
- 变更状态、作废单据和修改单据是不同操作；先判断目标状态和当前状态，不用作废代替状态调整。
- 标签新增与移除需要明确操作方向及标签对象，不能只根据标签名称猜测。
- 预约入库用于计划到仓；用户需要确认是否实际入库时查询采购入库，而不是只看预约状态。

## 结果呈现

- 采购单优先展示采购单号、供应商、采购状态、采购数量、已入库数量、未入库差额、金额和预计到货时间。
- 到货进度用“已入库数量 / 采购数量”和差额表达；预约入库只标为计划，不算实际到货。
- 供应商结果用名称与编号呈现；同名供应商并列，让用户按编号选择。
- 修改、状态变更、作废和标签操作分别描述实际动作，不能统一说成“采购单更新成功”。
- 批量结果按采购单或供应商拆分成功、失败和未知项；未知项提示查询采购单或后台核对。

## 典型问题

- “PO001 还差多少没到货？”：查询采购单并关联入库，给出采购、已入库、未到数量和当前状态。
- “这个供应商最近有哪些未完成采购？”：先确定供应商编号和时间范围，再汇总单数、数量与金额。
- “把待审核采购单的交期改到周五”：先查状态并携带官方要求的完整明细，回执中说明采购单号与新交期。
