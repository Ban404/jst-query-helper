# 库存

## 用户目标

按 SKU、仓库、箱或仓位核对库存，查询盘点结果，创建盘点单或更新虚拟库存。

## 能力路由

| 业务能力 | 类型 | action |
| --- | --- | --- |
| 商品库存查询 | 查询 | `inventory_query` |
| 箱及仓位库存查询 | 查询 | `webapi_wmsapi_pack_pagequerypackanditems` |
| 新建盘点单 | 写入 | `jushuitan_inventoryv2_upload` |
| 库存盘点查询 | 查询 | `inventory_count_query` |
| 导入或更新虚拟库存 | 写入 | `webapi_itemapi_iteminventory_batchupdatewmsvirtualqtys` |

## 执行要点

- 汇总时明确区分实际库存、订单占有、仓库待发、采购在途、锁定、安全库存、虚拟库存、可用数和可配货数，不能笼统称为“库存”。
- 用户问“还能卖多少”时优先解释可用数口径；问“仓库有多少实物”时使用实际库存；问“能配多少订单”时关注可配货数。
- 开通分仓后，主仓商品库存界面可能包含分仓库存。用户未指定仓库时按仓展示或明确汇总口径，避免重复累计。
- 箱及仓位库存全量拉取使用 `pack_item_id_begin` 游标并搭配 `page_size`，不得同时混入时间等其他筛选条件；零库存仓位记录可能已被系统删除。
- 新建盘点单前查询并确认仓库编码、SKU、批次和盘点数量；盘点数量与原库存无差异时，ERP可能不创建盘点记录。
- 库存盘点查询用于跟进盘点结果，不应把“盘点单已创建”直接描述为“库存已调整完成”。
- 更新虚拟库存只影响虚拟库存及线上同步口径，不等同于修改仓库实物库存。
- 跨仓、仓内移动使用[调拨](transfers.md)，运营云仓分配使用[虚拟仓](virtual-warehouse.md)，不要用盘点或虚拟库存更新替代调拨。

## 结果呈现

- 每条库存至少带 SKU 和仓库，按实际库存、可用库存、订单占用、锁定库存、虚拟库存、采购在途分别展示，禁止只给一个没有口径的“库存”。
- 多仓结果先按仓列出，再按用户明确要求决定是否合计；存在主仓包含分仓的可能时不做跨仓总和。
- 数量统一标注“件”或接口明确的单位；负虚拟库存、负盘点差异等异常值原样保留并解释含义。
- 查询为空时说明 SKU、仓库和时间/游标条件；盘点创建成功只说明单据已创建，不宣称库存已完成调整。

## 典型问题

- “A001 现在还能卖多少？”：回答可用库存，并同时列出实际库存和主要占用项说明口径。
- “北京仓和上海仓各有多少？”：按仓展示，不在可能重复累计时强行给总数。
- “盘点后少了多少货？”：查询盘点结果，展示账面数、盘点数、差异及处理状态。
