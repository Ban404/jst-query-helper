# Architecture

## In one line

Built around the fact that **a private ERP's account / login / authorization can't be bypassed**: the tool bypasses nothing. It reuses the login state already established on the machine and the query program bundled with the official client, and performs read-only queries.

## Data flow

```
User (plain language)
    │
    ▼
AI assistant (WorkBuddy / Goodax / DeepSeek / Harness, etc.)
    │  reads SKILL.md to decide the path
    ▼
skill/scripts/ask.py  ──scenario engine──┐       connector/server.mjs (MCP tools)
    │                                   │                  │
    │ health check                      │                  │
    ▼                                   ▼                  ▼
skill/scripts/jst.py                guide.json /      connector/ask.mjs
    │  locate token & CLI,             scenarios.json     (same scenarios, Node)
    │  fill revision, paginate,         (single source
    │  segment                          of wording)
    ▼
Shuibao's bundled query program jst-open-platform(.exe)
    │  with the local logged-in token
    ▼
JST ERP (query endpoints only)
    │
    ▼
Chinese summary + table + optional CSV
```

## Three entry points, one logic

| | Skill `skill/` | Connector `connector/` | Universal MCP `mcp/` |
| --- | --- | --- | --- |
| Language | Python 3.8+ | Node 18+ | Node 18+ |
| Entry | `jst.py` (core) + `ask.py` (scenarios) | `server.mjs` (MCP) + `ask.mjs` (scenarios) | `server.mjs` (MCP) + `ask.mjs` (scenarios) |
| For | Individual users, works on install | Enterprise users wanting MCP tools | Claude Desktop / Cursor / Cline and any MCP client |
| Runtime | Python 3.8+ | Node 18+ | User's Node 18+ |
| Publish | Universal AI assistant skill | MCP connector | npm / zip download |

**Consistency mechanism**: guidance lives only in `guide.json`, scenarios only in `scenarios.json`, endpoints only in `catalog/actions.json`. `tools/sync_core.py` generates the universal MCP package's `server.mjs` / `ask.mjs` from the connector core (only resource paths differ); `tools/build.py` copies the three catalogs into all three packages. The offline verifier compares byte-for-byte and CI checks the MCP core stays in sync with the connector. Change once, all three stay in sync. Each edition bundles its own README (zh/en), LICENSE and CHANGELOG for independent publishing.

## Key components

- **Health-check state machine**: `jst.py:cmd_doctor()` / `server.mjs:check()`. Checks 5 things in order — client installed → logged in → query program present → token valid → authorized. Stops at the first failure and returns user-ready wording (`what_to_do`/`who`/`url`/`success_check`).
- **Credential reuse**: `jst.py:resolve_token()`. Env var → in-package `config.json` (not distributed) → local Shuibao config. The upstream stores the JWT fully reversed; `normalize_token()` flips it back. Read-only, never uploaded, never written into the package.
- **CLI discovery**: `find_cli()` has 5 fallbacks (explicit env → in-package → Shuibao skill dir → old skill → recursive search) to survive upstream path changes.
- **Schema revision**: the upstream CLI requires `schema_revision` preflight. Scripts fetch it from `describe_action`, cache it (temp dir in Python, in-memory in Node), and refresh once on mismatch.
- **Read-only whitelist**: `catalog/actions.json` registers 89 endpoints (36 query / 53 write). Only `kind=query` is allowed; others return `READONLY_MODE` / `ACTION_NOT_ALLOWED`. A `READONLY` marker file is a second lock.
- **Scenario engine**: `ask.py` / `ask.mjs`. 9 built-in scenarios + generic `query`. Auto-splits long ranges into 7-day windows (upstream limit), auto-paginates, reads large results from `raw_data_path`, translates fields to Chinese, caps display at 50 rows, exports UTF-8 BOM CSV.

## Layout conventions

```
catalog/          endpoint catalog + domain docs (single source for three editions, by refresh_catalog.py)
skill/            【edition ①】skill package source (Python, self-contained)
connector/        【edition ②】connector package source (Node, self-contained)
mcp/              【edition ③】universal MCP package source (Node, self-contained, npm-publishable)
tools/            build / sync_core / refresh_catalog / verify_offline / verify_online / scan_secrets
tests/            offline unit tests (pytest)
docs/             quickstart / architecture / FAQ / scenarios / marketplace / recognition
dist/             build output (gitignored, generated by build.py)
```

## Maintenance flow

1. Upstream upgrade → `python tools/refresh_catalog.py` to re-detect endpoints, review the diff;
2. Wording → edit only `guide.json`; scenarios → only `scenarios.json` + engines (Python `ask.py`, Node connector `ask.mjs` then `sync_core.py` to MCP);
3. Run `python tools/verify_offline.py` + `python -m pytest tests/ -q`;
4. Live check only if needed: `python tools/verify_online.py`;
5. `python tools/build.py` auto-syncs cores and rebuilds all three zips.

CI (`.github/workflows/ci.yml`) runs offline checks, unit tests, and the privacy scan across multiple Python/Node versions.
