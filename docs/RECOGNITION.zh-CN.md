# 新版客户端重新识别报告

识别日期：2026-11-23。方式：全程只读——看安装目录与版本信息、从二进制提字符串、按 12 个业务域重新拉接口目录、跑完整自检。**没有改动上游程序任何文件。**

## 结论

聚水潭这条链路没有断，但有两处新规矩要适配：

- 登录凭据（倒序 JWT）、授权状态、89 个接口、12 份领域说明——逐项比对后**完全一致**；
- 新版查询程序要求 `list_actions` 按业务域读取，不能一次拿全部；
- 新版「聚水潭 ERP 助手」变成**技能市场技能**，不再是安装包自带文件，新电脑可能漏装；
- 新增的守护服务、DWS、钉钉技能都与聚水潭查询无关，**不接**。

## 主要变化

| 项目 | 影响 |
| --- | --- |
| 主程序升级到 2.0.611181 | 无 |
| 新增后台守护服务 `jxyservice.exe` | 新人会看到，写进安装话术说明是正常组件 |
| 新增 DWS 运行时、一批钉钉技能 | 无关，不接 |
| 聚水潭技能改为技能市场来源 | 关键：新电脑靠首次登录自动装，可能漏装 → `CLI_MISSING` 引导去技能市场装 |
| 连接器/连接记录表改为资产注册表 | 本地不再存连接记录；授权是服务端账号级，不受影响 |
| 登录凭据仍是整体倒序 JWT | 无需改动代码 |
| 查询程序路径不变 | 5 级查找仍有效 |
| 接口目录 12 域 / 89 接口 | 逐域重拉：名称、分类、所属域零变化 |
| `list_actions` 必须带 `--domain` | 不带报 `DOMAIN_REQUIRED` → 两份入口都改成自动按域汇总 |

## 适配动作

1. `catalog/actions.json` 由 `tools/refresh_catalog.py` 从新版查询程序按 12 域重新识别生成，工程自包含；
2. 技能包 `jst.py` 与连接器 `server.mjs` 的 `list_actions` 不带域时，自动「取 12 域 → 逐域取接口 → 合并」，新旧版都能用；
3. `CLI_MISSING` 引导改为「打开水宝 → 技能/技能市场 → 安装聚水潭 ERP 助手」；
4. 安装话术加「守护服务是正常组件」；
5. 版本统一升到 5.0.0。

## 复核方法

```bash
python tools/refresh_catalog.py   # 重新识别：脚本会打印与上一版的新增/移除/变化对比
python tools/build.py             # 重建两个 zip
python tools/verify_offline.py    # 纯离线自检
python tools/verify_online.py     # 装好客户端并授权后，真实环境自检
```

## 仍然成立的边界

1. 做不到「装完立刻出数据」：账号、本人登录、本人授权三道门绕不过去；
2. 登录约 7 天过期，重登即可；授权账号级一次性；
3. 只读：36 查询放行，53 写入和未登记接口拦截；
4. 目录路径不是官方承诺；代码做了 5 级查找，真变了改一处 + 跑一次 `refresh_catalog.py`；
5. `mcp.json` 的 `cwd` 相对基准官方未写死，上架后需自己启用一次确认工具出现；
6. 客户端下载页 <https://jxy.ai/download>（有 Windows 版）；公司统一安装包优先；
7. 连接器 `source` 要求平台全局唯一。
