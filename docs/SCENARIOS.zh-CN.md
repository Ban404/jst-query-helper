# 场景与接口

## 9 个开箱场景

| 命令 | 用户会这么问 | 得到什么 |
| --- | --- | --- |
| `overview [--days 7]` | 今天生意怎么样 / 总体情况 | 待发货 / 已发货 / 取消几单，哪几款快没货 |
| `pending [--days 30]` | 有没有货要发 / 哪些订单还没发 | 待发货订单，并判断卡在没审核、缺货还是没出库单 |
| `serials [--days 30] [--csv]` | 这个月发了哪些机器 / 序列号清单 | 销售出库单里的序列号，去重、按日期，可导 CSV |
| `sn --sn 序列号 [--days 90] [--csv]` | 这个 SN 是哪单发的 / 客户报了个 SN | 反查出库日期、订单号、物流单号、商品；可只输后几位 |
| `stock [--keyword 词] [--low 数量] [--days 7]` | 还有多少库存 / 哪些货快没了 | 按商品名 / 库存阈值筛选，从少到多排 |
| `order --id 订单号` | 这单发了吗 / 订单 xxx 什么情况 | 订单详情 + 出库单 + 序列号一次查齐 |
| `shops` | 我有几个店 / 店铺编号 | 店铺名称、编号、平台授权到期 |
| `query --action 接口 [--days 7] [--csv]` | 查售后 / 采购单 / 盘点单 / 调拨单 | 覆盖其余全部查询接口，自动分段翻页、字段翻中文 |
| `find 关键词` | 能不能查 XX | 在 89 个接口里按中英文关键词找能用的查询接口 |

`list` 场景会打印这份清单。所有联网场景都可加 `--days`（最多 180），带 `--csv` 导出。

## 全部查询接口

场景没覆盖时：先 `find 关键词` 找接口名，再 `query --action 接口名`。36 个查询接口全都能问。

按业务域分布（共 89 个接口，其中 36 查询 / 53 写入）：

| 业务域 | 接口数 | 业务域 | 接口数 |
| --- | --- | --- | --- |
| 基础信息 | 6 | 商品 | 15 |
| 订单 | 10 | 库存 | 5 |
| 售后 | 6 | 采购 | 12 |
| 入库 | 4 | 出库 | 5 |
| 其他出入库 | 3 | 调拨 | 6 |
| 虚拟仓 | 9 | 播种 | 8 |

每个域的字段说明见 [`../catalog/domains/`](../catalog/domains/) 里的 12 份文档；这些文档由上游客户端自带，`refresh_catalog.py` 会同步过来。

## 只读边界

- **36 个 `kind=query` 接口**放行（清单见 `catalog/actions.json`）；
- **53 个 `kind=write` 接口**（发货、审核、取消、改备注等）一律返回 `READONLY_MODE`；
- **任何未登记接口**返回 `ACTION_NOT_ALLOWED`；
- 这不是口头约定，是 Python / Node 两份入口各自的代码强制，外加包内 `READONLY` 标记文件。

## 输出约定

每个场景返回统一的 JSON：

```json
{
  "ok": true,
  "scenario": "待发货订单",
  "summary": "一句话中文结论（可以直接念给用户）",
  "count": 12,
  "rows": [ /* 整齐的表格数据，对话里最多 50 行 */ ],
  "truncated": false,
  "notes": [ /* 口径说明 */ ],
  "csv": ""
}
```

- `summary` 是给普通用户看的结论，讲数字和关键项，不贴 JSON。
- `rows` 是明细，用户要展开再给。
- 超过 50 行时 `truncated=true`，加 `--csv` 拿全量（UTF-8 BOM，Excel 直接打开不乱码）。

## 口径说明

- 时间按业务单据的**修改时间**统计，不是下单/出库时间。
- 接口一次最多查 7 天，脚本自动分段；一次任务最多往前 180 天。
- 同一单据在多个时间段出现会去重。
- 序列号挂在销售出库单上，订单接口里没有。
- 常见订单状态：`WaitConfirm`（已付款待审核）、`Confirmed`（已确认待发货）、`Sent`（已发货）、`Cancelled`（已取消）。
